## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6) and isolated environment (RUN1, RUN10, ENV6):** the primary path performs no clone, repository install or repository import, and installs nothing into the notebook kernel. Section 2 of each notebook writes `src/tabicl_regressor_pipeline/{__init__,api}.py`, the notebook's stage runner, the hash-locked `requirements-colab.lock.txt`, the one-file SHA-256 snapshot manifest and the licence (the companion also the pinned sample bundle; the E2E notebook its provenance record) into a run directory and verifies each against its SHA-256 (`CARRIED_HASHES`); a pinned `uv` wheel (size + SHA-256) builds a managed-CPython virtual environment from the lock with `--require-hashes`, keyed on the lock's digest so a second Run all reuses it, and every learner cell runs one stage of the stage runner in its own process (`run_stage`). Re-running the Section 1 cell keeps the run directory. `metadata.dimer.generated_from` records the repository, the generating commit, the package SHA-256, the carried-file digests and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py`, `tests/test_companion_parity.py` and `tools/validate_release_assets.py` fail when a carried file (package module, stage runner, lock, manifest, sample bundle) differs from the repository, when the lock does not pin every `pyproject.toml` runtime pin with hashes, or when a notebook is not byte-identical to the generator's output for its template.
- **Model acquisition:** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entry that is absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes it and asserts the manifest digest equals the package's `BASE_MODEL_SHA256`; `TabICLRegressionPipeline.from_pretrained(weights_dir=WEIGHTS_DIR, ...)` constructs the upstream estimator on the verified file with `allow_auto_download=False`. The previous `CHECKPOINT_SOURCE = "DIMER ZIP"` option is replaced by the snapshot directory: place the pinned `.ckpt` there and nothing is downloaded.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/<stem>_input_manifest.json` with the schema, the observed structure of every table (blank-target rows dropped before a single-CSV split are carried into the manifest; present-but-unparseable targets, including thousands separators, are refused rather than dropped — DAT23, VAL5), the verdict and one recorded rejection finding; `evaluation_report` (EVAL21) writes `outputs/<stem>_evaluation_report.json` — `sample-sanity` with `mae` / `mse` / `rmse` / `r2` / `pearsonr`, the independent-test block and the training-mean baseline in the E2E notebook (classical baselines and the blend are attached), `not-measurable` (with what labelled data would make the task measurable) in the companion.
- **Artifact-inference companion (§18):** the bundle is supplied from outside the execution — by default the pinned sample bundle (`examples/sample-bundle/`, produced by `tools/build_sample_bundle.py` with the E2E notebook's own split, encoders and manifest code; no model was run, so its `metrics` are `null`; it declares `mode: pretrained`, so its checkpoint is the digest-verified base checkpoint and is not duplicated in the repository), otherwise a ZIP by `ARTIFACT_ZIP_PATH` or upload, checked against `EXPECTED_ZIP_SHA256` before extraction — extracted member by member by `safe_extract_zip` only after path/symlink/size checks (never `extractall`), verified by `verify_artifact_bundle` and `validate_artifact_runtime`, and compared with the carried pinned base-model identity before any model state is reconstructed (a `pretrained` bundle whose checkpoint digest differs from the base checkpoint's is refused); numeric feature columns holding text are refused naming the column; reconstruction uses the bundled checkpoint with `allow_auto_download=False` (no network fallback); no bundle is created and no fine-tuning happens in the companion.
- Regression obligations (Notebook Specification §20.2): the target is validated as finite numeric and varying before the model runs, MAE and RMSE are reported in target units with R² alongside, and the notebooks state that predictions are point estimates with no uncertainty interval.
- `USE_BYOD` and `RUN_NEW_DATA_INFERENCE` default to `False` so the E2E sample path never opens an upload dialog. `RUN_FINE_TUNING` defaults to `True`: on a CUDA runtime the default path runs the pipeline's production adaptation (bounded to 3 epochs and 300 seconds, early stopping, holdout-only selection); without CUDA the stage records why it was skipped. The companion's default path uses the pinned sample bundle and rows, so it opens no upload dialog either. Both accept paths that work outside Colab.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.

## Main tutorial

- exact pinned `tabicl-regressor-v2-20260212.ckpt` acquisition through the manifest-driven snapshot (`stage_missing_files` + `verify_snapshot`)
- Diabetes sample (default), California Housing subsample, or BYOD CSV / pre-split `train.csv`/`val.csv`/`test.csv`
- finite numeric-target validation with dropped-row counting, row/feature ceilings and a training-target variation check (`validate_inputs`, `prepare_regression_table`)
- pretrained in-context evaluation with MAE, MSE, RMSE, R², and Pearson correlation (`regression_metrics`)
- optional `FinetunedTabICLRegressor` CUDA fine-tuning behind `RUN_FINE_TUNING` with holdout-only selection (`compare_metric`); independent test is evaluation only
- companion classical tree baselines (LightGBM and Random Forest) with holdout leaderboard and device latency
- in-memory post-hoc point-prediction blending with holdout RMSE minimisation and generalisation assessment
- `evaluation_report` with the training-mean baseline, the classical baselines and the blend attached
- optional new-data point prediction behind `RUN_NEW_DATA_INFERENCE` (inference-mode `validate_inputs`)
- DIMER-style bundle export: checkpoint + training context + manifest (digests, sizes, payload allowlist, producer runtime)
- fresh reload through `safe_extract_zip` + `verify_artifact_bundle` with a prediction-equivalence check

## Artifact contract

TabICL remains an in-context learner after downstream fine-tuning. A deployable bundle therefore requires at minimum:

```text
checkpoints/best.ckpt
training_context.parquet
artifact.json
```

The inference-only notebook verifies internal digests, reconstructs the support context, and calls the ordinary TabICL estimator with `allow_auto_download=False`. The E2E export stage prints the ZIP's SHA-256 (the value to give the companion as `EXPECTED_ZIP_SHA256`) and, on the default sample, whether its training context is byte-identical to the pinned sample bundle's.

## Trust boundary

ZIP path checks prevent traversal and symlink extraction, but they do not make model deserialization trustworthy. Load only artifacts you produced yourself or obtained from a trusted source. When a known ZIP SHA-256 is available, compare it before extraction/loading.

The portable artifact also embeds the labelled training context. Treat the exported ZIP with the same dataset licence, access-control, retention, and disclosure requirements as the source training data.

## Runtime evidence
